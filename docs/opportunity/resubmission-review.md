# Saving requested changes

After Sales Head requests changes, the creator edits the opportunity and clicks
**Update Opportunity**. That save persists the details, moves Identified / Changes
Requested (1 / 2) to Pending Review (1 / 1), and records the event in the existing
engagement tracker in one transaction. This includes Sales Head creators.

CEO-requested corrections return to CEO / Pending Go/No-Go (2 / 4) on update,
preserving Sales Head approval. Other permitted updates keep their workflow stage.
Edit permission applies at every stage. Sales Representatives can edit their own
opportunities; other roles with Edit permission can edit any opportunity. Saving
another creator's Sales Head corrections preserves Changes Requested until the
creator saves. Approved and later-stage saves preserve their workflow stage.

CEO change requests are addressed to Sales Head. Sales Head can edit and save the
corrections to return the opportunity directly to CEO review. While changes are
requested, CEO retains Approve, On Hold and Reject actions; Request Changes keeps
its selected appearance. These controls are visible only to the authorized role.

There is no separate Resubmit for Review button and no new database column,
function, or migration. The save success message identifies the reviewer when
corrections return for review. Review decision actions do not show success messages.
Legacy RESUBMIT requests direct callers to Update Opportunity.
